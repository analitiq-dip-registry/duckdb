# THIS connector's own driver and dialect packages (the engine pins no database
# drivers). This repo ships no connector class and no pyproject.toml, so this
# file IS its dependency declaration: the engine's entrypoint installs a
# connector directory that has no pyproject.toml with `pip install -r
# requirements.txt`, and the registry's conformance job reads it the same way.
# Never list SQLAlchemy or the CDK here — the engine environment provides both.

# duckdb_engine registers the "duckdb" SQLAlchemy dialect. DuckDB's transport is
# SQLAlchemy (`driver: duckdb` in connector.json), and the engine's shared read
# path (GenericSQLConnector.read_batches -> QueryBuilder) resolves the dialect
# via sqlalchemy.dialects.registry.load("duckdb"). "duckdb" is not a SQLAlchemy
# built-in, so without this package every source read raises ImportError before
# the first page.
#
# Floor 0.13.0: the oldest release verified against this connector. No
# duckdb_engine release caps SQLAlchemy — every one of them declares only
# sqlalchemy>=1.3.22 — so an unbounded requirement lets pip resolve a
# pre-2.0-era dialect against the CDK's sqlalchemy>=2.0,<3.
duckdb-engine>=0.13.0

# The DBAPI itself. duckdb_engine depends on it (duckdb>=0.5.0), but that floor
# is not this connector's: this repo's read type map claims UHUGEINT, which
# DuckDB added in 0.10.0 (0.9.2 answers "Catalog Error: Type with name UHUGEINT
# does not exist"). Pinning it here keeps the type map's vocabulary and the
# installed engine from drifting apart.
duckdb>=0.10.0
